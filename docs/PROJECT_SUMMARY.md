## 1. 项目全景概览

### 1.1 一句话定义

**TaskFlow** 是一个面向编程新手的全栈实战项目——一个简洁、高效的个人任务管理系统，帮助用户管理日常待办事项。

### 1.2 项目定位

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   对用户：轻量级个人任务管理工具，零门槛上手                    │
│                                                             │
│   对开发者：完整的全栈开发实践，从需求到部署的端到端体验          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 技术栈一览

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| **前端框架** | React 18 + TypeScript | 主流框架，类型安全 |
| **构建工具** | Vite 5 | 极速开发体验 |
| **样式方案** | Tailwind CSS 3 | 原子化 CSS，高效开发 |
| **后端框架** | Express 4 + TypeScript | 生态成熟，学习资源丰富 |
| **数据库** | SQLite (better-sqlite3) | 零配置，文件存储，新手友好 |
| **参数校验** | Zod | TypeScript 友好的类型推导校验 |
| **图表库** | Recharts | React 声明式图表 |
| **日期处理** | Day.js | 轻量级（2KB） |

## 4. 技术架构总结

### 4.1 整体架构

```
浏览器（React + Tailwind CSS）
         │
         │  HTTP RESTful API (JSON)
         ▼
Express 应用服务器（Node.js）
    Routes → Controllers → Services
         │
         ▼
SQLite 数据库文件（taskflow.db）
    tasks 表 + categories 表
```

### 4.2 分层架构

| 层级 | 职责 | 关键文件 |
|------|------|----------|
| **路由层** | URL 映射 + 中间件挂载 | `routes/taskRoutes.ts`、`routes/categoryRoutes.ts` |
| **控制器层** | 解析请求、调用服务、返回响应 | `controllers/taskController.ts` |
| **服务层** | 业务逻辑 + 数据库操作 | `services/taskService.ts`、`services/categoryService.ts` |
| **中间件** | 错误处理、参数校验、CORS | `middleware/errorHandler.ts`、`middleware/validate.ts` |
| **数据层** | 数据库连接与初始化 | `config/database.ts` |

### 4.3 项目结构

```
taskflow/
├── client/                    # 前端
│   ├── src/
│   │   ├── api/               # API 调用封装
```

### 4.4 API 接口总览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/tasks` | 获取任务列表（支持筛选/排序/搜索） |
| POST | `/api/tasks` | 创建任务 |
| GET | `/api/tasks/:id` | 获取任务详情 |
| PUT | `/api/tasks/:id` | 更新任务 |
| PATCH | `/api/tasks/:id/status` | 快速切换状态 |
| DELETE | `/api/tasks/:id` | 删除任务 |
| GET | `/api/categories` | 获取分类列表 |
| POST | `/api/categories` | 创建分类 |
| PUT | `/api/categories/:id` | 更新分类 |
| DELETE | `/api/categories/:id` | 删除分类 |
| GET | `/api/stats` | 获取统计数据 |

## 5. 功能模块总结

### 5.1 任务管理（核心）

```
创建任务 ──→ 列表展示 ──→ 编辑/删除
                │
                └──→ 状态流转：TODO → IN_PROGRESS → DONE
```

| 能力 | 说明 |
|------|------|
| CRUD | 完整的增删改查，模态框交互 |
| 状态流转 | 三态循环切换，一键操作 |
| 筛选 | 按状态、分类、优先级筛选 |
| 排序 | 按创建时间、优先级、截止日期排序 |
| 搜索 | 标题关键词模糊搜索（300ms 防抖） |

### 5.2 属性管理

| 能力 | 说明 |
|------|------|
| 分类管理 | 4 个预置分类 + 自定义分类增删改 |
| 优先级 | 高（红）/ 中（橙）/ 低（绿）三级 |
| 截止日期 | 日期选择器，支持过期视觉提醒 |

### 5.3 截止日期提醒

| 条件 | 视觉表现 |
|------|----------|
| 截止 > 7 天 | 正常灰色 |
| 截止 ≤ 7 天 | 橙色警告 |
| 已过期 + 未完成 | 红色 + "已过期"标签 |
| 已过期 + 已完成 | 正常显示（不警告） |

### 5.4 统计面板

| 指标 | 可视化 |
|------|--------|
| 任务总数 / 各状态数量 | 数字卡片 |
| 完成率 | 进度条 / 环形图 |
| 今日完成 / 逾期数 | 数字卡片 |
| 各分类任务数 | 水平柱状图 |

## 6. 开发流程总结

### 6.1 开发阶段与里程碑

```
Day 1            Day 2           Day 3           Day 4           Day 5
基础搭建          后端 API        前端页面         前后端联调       优化打磨
─────────────────────────────────────────────────────────────────────────
│ M1 基础搭建 │ M2 后端 API │ M3 前端页面  │ M4 联调完成  │ M5 统计 │ M6 交付 │
└─────────────────────────────────────────────────────────────────────────
```

| 阶段 | 核心任务 | 产出物 | 完成标志 |
|------|----------|--------|----------|
| **Day 1** | 项目初始化、数据库、Express 框架 | 可运行的前后端骨架 | `npm run dev` 启动无报错 |
| **Day 2** | 分类 + 任务全套 API | 11 个 RESTful 接口 | curl 测试全部通过 |
| **Day 3** | 布局、列表、表单、模态框 | 完整的前端页面 | 硬编码数据正确渲染 |
| **Day 4** | API 对接、筛选搜索、统计面板 | 功能完整的应用 | CRUD + 筛选全通 |
| **Day 5** | 响应式、Toast、边界处理 | 可交付的产品 | 所有验收标准通过 |

### 6.2 开发顺序原则

```
后端：类型定义 → Schema → Service → Controller → Route
前端：类型定义 → 组件骨架 → 硬编码渲染 → 接入 API → 交互完善
联调：Hook 封装 → CRUD 对接 → 筛选搜索 → 状态切换 → 统计面板
```

### 6.3 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 项目结构 | Monorepo | 单仓库管理，降低新手认知负担 |
| 数据库 | SQLite | 零配置、文件存储、学习成本低 |
| 状态管理 | React Context | 项目规模适中，无需 Redux |
| CSS 方案 | Tailwind CSS | 原子化开发，效率高 |
| 参数校验 | Zod | TypeScript 类型推导，前后端可共享 Schema |
| 图表库 | Recharts | 基于 React，声明式 API 简洁 |
| TS 运行 | tsx | 开发阶段无需编译，直接运行 TS |

## 8. 部署交付总结

### 8.1 四种部署方案

| 方案 | 难度 | 成本 | 公网 | 适合 |
|------|------|------|------|------|
| **本地部署** | ★☆☆☆☆ | 免费 | 否 | 新手入门、个人使用 |
| **Docker 容器** | ★★★☆☆ | 免费 | 可选 | 生产推荐、环境隔离 |
| **云平台分离** | ★★★★☆ | 低 | 是 | 前端 CDN 加速 |
| **云服务器单机** | ★★★☆☆ | 中 | 是 | 完全控制 |

### 8.2 推荐路径

```
新手入门 → 本地部署（5 分钟跑起来）
    ↓
学习进阶 → Docker 容器（理解容器化）
    ↓
公网访问 → 云平台 或 云服务器
    ↓
自动化 → CI/CD（GitHub Actions 自动部署）
```

### 8.3 部署关键文件

| 文件 | 用途 |
|------|------|
| `Dockerfile` | Docker 镜像构建 |
| `docker-compose.yml` | Docker 一键编排 |
| `ecosystem.config.js` | PM2 进程管理配置 |
| `taskflow.service` | Systemd 服务配置 |
| `nginx/sites-available/taskflow` | Nginx 反向代理配置 |
| `.github/workflows/deploy.yml` | CI/CD 自动化部署 |
| `scripts/backup.sh` | 数据库自动备份脚本 |
| `scripts/smoke-test.sh` | 部署后冒烟测试脚本 |
| `scripts/update.sh` | 一键更新脚本 |

### 8.4 数据安全

| 措施 | 说明 |
|------|------|
| 自动备份 | 每天凌晨 2 点自动备份数据库 |
| 保留策略 | 只保留最近 7 天的备份 |
| 持久化 | Docker Volume / 服务器磁盘 |
| 回滚 | 支持代码回滚 + 数据库恢复 |

## 11. 新手上手指南

### 11.1 快速开始（3 步跑起来）

```bash
# 1. 安装依赖
cd taskflow
cd server && npm install && cd ../client && npm install && cd ..

# 2. 一键启动
npm run dev

# 3. 打开浏览器
# http://localhost:5173
```

### 11.2 学习路线图

```
第 1 天：理解项目
├── 阅读 PRD（§1~§3），理解要做什么
├── 阅读实施计划（§1 架构），理解技术选型
└── 跑起来项目，体验功能

第 2 天：理解代码
├── 阅读开发规范（§2 命名），理解文件在哪
├── 从后端入口 server/src/index.ts 开始，跟踪请求流程
└── 从前端入口 client/src/App.tsx 开始，跟踪页面渲染

第 3 天：开始开发
├── 按实施计划 Day 1 任务，搭建基础框架
├── 遇到问题查阅开发规范对应章节
└── 每完成一个功能，对照测试计划验证

第 4~5 天：完成功能
├── 按实施计划逐日推进
├── 使用测试计划的用例自测
└── 最后用部署计划上线

持续：查阅参考
├── 编码问题 → 查开发规范
├── 功能问题 → 查 PRD
├── 测试问题 → 查测试计划
└── 部署问题 → 查部署计划
```

### 11.3 关键概念速查

|------|------|------|

## 12. 后续演进方向

### 12.1 v1.1 潜在功能

| 方向 | 说明 |
|------|------|
