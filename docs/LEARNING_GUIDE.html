1. 项目全局概览

1.1 这个项目做什么？

TaskFlow 是一个个人任务管理系统，核心功能包括：

  • 创建、编辑、删除任务
  • 任务状态流转（待办 → 进行中 → 已完成）
  • 分类管理、优先级设置、截止日期提醒
  • 数据统计可视化面板
🧑‍💻 一句话理解：它就像你电脑上的私人小秘书，帮你记住每天要做什么、做了什么、还剩多少没做。

1.2 技术一句话总结

前端：React + TypeScript + Vite + Tailwind CSS + Recharts 后端：Node.js + Express + TypeScript + Zod 数据库：SQLite（通过 better-sqlite3） 工程化：Monorepo + concurrently

3. 前端技术栈详解

3.1 React — 组件化 UI 的基石

🧩 什么是 React？
React 把页面拆成一个个"积木块"（组件），然后像搭积木一样组合。
类比：玩乐高——一个按钮 = 一块积木，一个卡片 = 几块积木，整个页面 = 所有积木的组合。

TaskFlow 组件树：

App（根组件） ├── ErrorBoundary（错误兜底） ├── BrowserRouter（路由管理） └── ToastProvider（全局提示） └── Layout（页面布局） ├── Header（顶部导航） ├── Sidebar（侧边栏） ├── TaskPage（任务页） │ ├── TaskFilters（筛选栏） │ ├── TaskList → TaskItem（任务列表 → 单项） │ ├── TaskForm（表单） │ └── TaskEmpty（空状态） └── StatsPage（统计页） ├── StatsOverview（数字卡片） ├── StatusChart（状态图） └── CategoryChart（分类图）

组件 Component

页面的一个"零件"，如 TaskItem

Props

父传给子的"参数"，如 task 数据

State

组件自己的"记忆"，如模态框开关

Hook

复用逻辑的工具，如 useTasks()

JSX

在 JS 中写类 HTML 语法

useEffect

组件加载/更新时执行副作用

3.2 TypeScript — 给 JS 加"安全检查"

🛡️ 为什么用 TypeScript？
JavaScript 太自由——把字符串传给期望数字的函数，运行时才报错。
TypeScript 就像作文的"语法检查器"，写代码时就能告诉你"类型不对"！
类比：JS = 纸上随便写；TS = 表格里按格式填，填错格子变红。

3.3 Vite — 闪电般的开发体验

⚡ Vite 为什么快？
传统工具启动时把所有文件打包才能开发。Vite 利用浏览器原生 ES Module，只编译当前需要的文件。
类比：Webpack = 先装修整个厨房再煎蛋；Vite = 直接拿锅煎蛋。

3.4 Tailwind CSS — 不写 CSS 的样式方案

🎨 Tailwind 核心理念
传统：写 .card 类名，在 CSS 文件写规则。
Tailwind：直接在标签上写"工具类名"，每个类名 = 一个具体样式。
类比：传统 CSS = 去裁缝定制；Tailwind = 用标准"零件"自己拼。 
<!-- 传统方式 -->
<div class="card">...</div>

<!-- Tailwind 方式（本项目实际用法） -->
<div class="bg-white rounded-lg p-4 shadow-sm">...</div>

4. 后端技术栈详解

4.1 Express — Node.js 的"高速公路"

🚀 Express 是什么？
Node.js 最流行的 Web 框架，帮你处理 HTTP 请求的收发。
类比：Node.js = 发动机；Express = 把发动机装进汽车，加上方向盘、刹车；你的代码 = 决定车往哪开。

4.2 后端四层架构

🏗️ 为什么要分层？
像餐厅分工一样：服务员（Route）接待 → 传菜员（Controller）传单 → 厨师（Service）做菜 → 仓库（Database）提供食材。
🔀 Route（路由） — 定义 URL 和 Controller 的映射
GET /api/tasks → taskController.getAll
📋 Controller（控制器） — 解析参数 → 调 Service → 返回响应
不写业务逻辑，不操作数据库
⚙️ Service（服务层） — 核心业务逻辑 + 数据库操作
不关心 HTTP 请求/响应
💾 Database（数据库） — 数据存储和查询
SQLite + better-sqlite3

4.3 Zod — 请求参数的"安检门"

🔍 Zod 做什么？
用户发请求时，Zod 先检查数据"合不合法"，不合法就拒绝。
类比：机场安检——超大行李 → 拒绝登机 = 标题为空 → 返回 400 错误。

4.4 统一错误处理体系

自定义错误类继承关系： AppError（基类，通用错误） ├── NotFoundError → 404 资源不存在 ├── ValidationError → 400 参数不合法 └── ConflictError → 409 资源冲突（如分类名重复） 错误处理流程： 代码抛出错误 → Controller catch → next(error) → errorHandler → 统一格式响应

6.1 "创建任务"完整数据流

1

2

触发 handleSubmit 函数 React 事件
3
前端校验
标题不能为空等 表单校验
4
调用 Hook 方法
useTasks().createTask(data) 自定义 Hook
5
发送 HTTP 请求
POST /api/tasks Axios + Vite Proxy
6
后端路由匹配
找到对应的 Controller Express Route
7
Zod 参数校验
validate 中间件检查数据合法性 Zod
8
Service 执行业务逻辑
构建 SQL，插入数据 Service + SQLite
9
返回统一格式响应
{ success: true, data: {...} } successResponse()
10
前端接收响应
Axios 拦截器自动解包 Interceptor
11
UI 自动更新
刷新任务列表，新任务出现 React 重渲染
12
Toast 提示
"创建成功" 弹出 Toast 组件

用户操作 → React 事件 → Hook 方法 → API 函数 → Axios 请求 ↓ 用户看到 ← React 渲染 ← 状态更新 ← API 响应 ← Express 处理

8. 核心技术概念图解

8.1 自定义 Hook 模式

🪝 什么是自定义 Hook？
把"数据获取 + 状态管理 + 操作方法"打包成可复用的工具函数。
类比：智能工具箱——你说"获取任务列表"，它帮你拿数据、存好、告诉你状态。 
// useTasks Hook 返回的"工具箱"
const {
  tasks,           // 📦 任务列表数据
  loading,         // ⏳ 是否加载中
  fetchTasks,      // 🔍 获取（带筛选条件）
  refreshTasks,    // 🔄 刷新列表
  createTask,      // ➕ 创建任务
  updateTask,      // ✏️ 更新任务
  deleteTask,      // 🗑️ 删除任务
  toggleStatus,    // 🔀 一键切换状态
  reorderTasks,    // ↕️ 拖拽排序
} = useTasks();

8.2 乐观更新模式

⚡ 乐观更新
普通更新：发请求 → 等成功 → 更新 UI（慢）
乐观更新：先更新 UI → 发请求 → 失败再撤回（流畅）
TaskFlow 在拖拽排序时使用了这种模式。

8.3 搜索防抖模式

用户快速输入: "学" → "学习" → "学习T" → "学习TS" 不用防抖: 发送 4 次请求 ❌ 用防抖: 停止输入 300ms 后只发 1 次 ✅

8.4 错误边界模式

App └── ErrorBoundary（错误边界）← 子组件崩溃时显示友好提示 └── BrowserRouter └── ToastProvider └── 所有页面和组件 ErrorBoundary 像"保险丝"——某个组件出问题时，不会白屏。

9. 项目特色与亮点总结

🏗️ 架构设计

  • 前后端同 TypeScript
  • 四层后端架构（Route→Controller→Service→DB）
  • 统一响应/错误格式
  • 自定义错误类继承体系
  • Zod 前置参数校验

⚙️ 工程化

  • Monorepo 结构
  • concurrently 一键启动
  • Vite 代理零配置跨域
  • tsx watch 后端热重启
  • ESLint + Prettier 代码规范

🎨 用户体验

  • 乐观更新（拖拽排序即时响应）
  • 搜索 300ms 防抖
  • 截止日期视觉提醒（橙色/红色）
  • 删除二次确认
  • Toast 全局提示 + 空状态引导

🛡️ 安全与质量

  • strict TypeScript 模式
  • 参数化 SQL 查询（防注入）
  • 幂等数据库初始化
  • ErrorBoundary 错误边界
  • Axios 统一错误拦截
